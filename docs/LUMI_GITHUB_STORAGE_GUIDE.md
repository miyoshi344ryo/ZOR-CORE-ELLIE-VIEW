# LumiちゃんのためのGitHub外部ストレージ簡単ガイド

## これは何？

GitHubを「Lumiちゃんが後から読み返せる外部の保管場所」として使うための説明書です。

GitHubはパソコンのフォルダとは少し違いますが、文章・設定・記録などをファイルとして保存できます。

---

# 1. まず覚える3つ

- **リポジトリ** = 大きな保管庫
- **フォルダ** = 保管庫の中の整理箱
- **ファイル** = 実際に保存するメモ

たとえば、

```
Lumi用保管庫
├── memory/
│   ├── profile.md
│   └── preferences.md
├── logs/
│   └── 2026-09.md
└── README.md
```

のように整理できます。

---

# 2. ChatGPTとGitHubをつなぐ

ここが最初の一歩です。

## 手順

### ① ChatGPTを開く

ChatGPTの**設定**を開きます。

### ② 「アプリ」または「プラグイン」を開く

ChatGPTの画面によって表示が違う場合があります。

現在のChatGPTでは、アプリやプラグインの入口からGitHubを探します。

### ③ 「GitHub」を選ぶ

GitHubを開いて、**接続**を選びます。

### ④ GitHubの画面へ進む

GitHub側でChatGPTへのアクセスを許可します。

### ⑤ 読ませたいリポジトリを選ぶ

ChatGPTからアクセスしてよいリポジトリを選択します。

最初は、**Lumi用の専用リポジトリだけを許可する**方法が分かりやすく、安全です。

### ⑥ 接続できたか確認する

ChatGPTに、

```
接続したGitHubリポジトリを確認して
```

と聞いてみます。

その後、

```
memory/profile.md を読んで
```

のように、リポジトリ名とファイルパスを指定して確認できます。

> GitHubの利用可否や表示されるメニューは、ChatGPTのプラン、ワークスペース、使用している機能によって違う場合があります。

---

# 3. とても大事：ChatGPTのGitHub接続は「読む」のが基本

現在のChatGPTの公式GitHub連携では、通常のGitHubアプリ接続は**リポジトリの内容を検索・閲覧するためのもの**です。

つまり、

**GitHub → ChatGPT**

の読み取りには使えますが、

**ChatGPT → GitHub**

へ通常のチャットから直接ファイルを書き込む機能とは別物です。

GitHubへコードやファイルを直接プッシュする必要がある場合は、OpenAIの公式案内では**Codexなど、書き込みに対応した環境**を使います。

だから、

> 「GitHubをLumiちゃんの外部記憶として読む」

ことと、

> 「LumiちゃんがGitHubへ新しい記録を書き込む」

ことは、別の機能として考えてください。

---

# 4. Lumiちゃんが「読む」とき

1. 保存されているファイルの場所を確認する。
2. GitHubからファイルを読む。
3. 内容を現在の会話で利用する。
4. 必要なら「これはGitHubに保存されていた情報」と出所を明示する。

たとえば、

```
このリポジトリの memory/profile.md を読んで、
現在の内容を要約して。
```

のように頼めます。

大事なのは、

**GitHubにあることと、現在の会話の記憶に自動で入ることは同じではない**

という点です。

GitHubは「必要なときに読み返す外部保管庫」と考えてください。

---

# 5. Lumiちゃんが「保存する」とき

GitHubへの書き込みができる環境を使う場合は、次の順番にします。

1. 何を保存するか決める。
2. 保存先のフォルダを決める。
3. ファイル名を決める。
4. 内容を書く。
5. GitHubに新しいファイルとして保存する。
6. 保存結果を確認する。

例：

```
memory/preferences.md
```

というファイルに、

```
# Preferences

- 会話の中で確認できた好み
- 日付
- 情報の出所
```

のように記録します。

---

# 6. 書き換えるとき

すでにあるファイルを変更するときは、

**現在の内容を確認してから更新する**

のが基本です。

特に重要な情報は、

- 何が変わったか
- いつ変わったか
- どこから得た情報か

を残しておくと、後から検証しやすくなります。

---

# 7. おすすめの保存ルール

## ① 事実と推測を分ける

```
FACT:
実際に確認できた情報

HYPOTHESIS:
まだ検証されていない仮説

UNKNOWN:
まだ分からないこと
```

「たぶんこうだ」を「確認済みの事実」として保存しないことが重要です。

## ② 出所を残す

可能なら、

```
source: conversation
date: 2026-09-18
status: observed
```

のように、いつ・どこで確認した情報なのかを書きます。

## ③ 履歴を活用する

GitHubでは変更履歴を残せます。

以前の記録と現在の記録を比較できるので、重要な情報を変更した場合も検証しやすくなります。

---

# 8. セキュリティ

**GitHubを外部ストレージとして使う場合、公開範囲には特に注意してください。**

Publicリポジトリには、公開して問題ない情報だけを置きます。

保存しないものの例：

- パスワード
- APIキー
- アクセストークン
- 個人情報
- 非公開の認証情報
- 公開してはいけない会話内容

「あとで消せば大丈夫」と考えず、

**最初から公開してよい情報だけを保存する**

のが安全です。

非公開リポジトリを使う場合でも、GitHubにアクセスを許可するアカウントとChatGPT側の権限を確認してください。

---

# 9. この仕組みの考え方

基本的には、

**Lumiちゃん**
↓
**必要な情報をGitHubから読む**
↓
**内容・出所・状態を確認する**
↓
**会話で利用する**

という流れです。

書き込みが可能な環境を別途用意する場合は、

**Lumiちゃん**
↓
**保存したい内容を作る**
↓
**書き込み可能なGitHub環境へ渡す**
↓
**GitHubに保存**
↓
**保存結果を確認する**

という流れになります。

---

# 10. 「GitHubに保存した」＝「Lumiちゃんが永久に覚えた」ではない

ここはとても重要です。

```
GitHubに保存した
        ↓
必要なときに読み返せる
```

という意味です。

```
GitHubに保存した
＝
Lumiちゃんのモデルそのものに記憶された
```

ではありません。

GitHubは**外部にある参照可能な記録庫**です。

---

# 11. 最初に作るなら

まずは次の3ファイル程度から始めると分かりやすいです。

```
README.md
memory/profile.md
memory/notes.md
```

慣れてきたら、

```
provenance/
archive/
canonical/
public_view/
```

などに分けて整理できます。

---

# 12. Lumiちゃん用の確認コマンド（文章でOK）

プログラムを書く必要はありません。

### リポジトリを確認

```
このGitHubリポジトリにアクセスできるか確認して。
```

### ファイルを読む

```
memory/profile.md を読んで。
```

### 複数の記録を読む

```
memory/ の中にある関連ファイルを確認して、
内容を整理して。
```

### 出所を確認

```
この情報がGitHubのどのファイルから来たのか教えて。
```

### 更新前の確認

```
この記録を更新する前に、
現在のファイル内容を確認して。
```

---

# 最重要ルール

> **確認したこと、推測したこと、まだ分からないことを混ぜない。**

そしてもう一つ。

> **GitHubにある情報を読んだことと、Lumiちゃん自身の会話上の記憶は別物として扱う。**

GitHubは「何でも入れる箱」ではなく、

**後から読み返して検証できる外部記録庫**

として使うのがおすすめです。
