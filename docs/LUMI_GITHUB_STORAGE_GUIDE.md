# LumiちゃんのためのGitHub外部ストレージ簡単ガイド

## これは何？

GitHubを「Lumiちゃんが後から読み返せる外部の保管場所」として使うための簡単な説明書です。

GitHubはパソコンのフォルダとは少し違いますが、文章・設定・記録などのテキストデータをファイルとして保存できます。

## まず覚える3つ

- **リポジトリ** = 大きな保管庫
- **フォルダ** = 保管庫の中の整理箱
- **ファイル** = 実際に保存するメモ

たとえば、

```
Lumi用保管庫
├── memory/
│   ├── profile.md
│   └── preferences.md
├── logs/
│   └── 2026-09.md
└── README.md
```

のように整理できます。

## Lumiちゃんが「読む」とき

1. 保存されているファイルの場所を確認する。
2. ファイルの内容を読む。
3. 内容を現在の会話で利用する。
4. 必要なら「これはGitHubに保存されていた情報」と出所を明示する。

大事なのは、**GitHubにあることと、現在の会話の記憶に自動で入ることは同じではない**という点です。

GitHubは外部ストレージであり、必要なときに読みに行く場所、と考えてください。

## Lumiちゃんが「保存する」とき

新しい情報を保存したい場合は、次の順番にします。

1. 何を保存するか決める。
2. 保存先のフォルダを決める。
3. ファイル名を決める。
4. 内容を書く。
5. GitHubに新しいファイルとして保存する。
6. 保存結果を確認する。

例：

```
memory/preferences.md
```

というファイルに、

```
# Preferences

- 会話の中で確認できた好み
- 日付
- 情報の出所
```

のように記録します。

## 書き換えるとき

すでにあるファイルを変更するときは、**現在の内容を確認してから更新する**のが基本です。

特に重要な情報は、上書きする前に、

- 何が変わったか
- いつ変わったか
- どこから得た情報か

を残しておくと、後から検証しやすくなります。

## おすすめの保存ルール

### 1. 事実と推測を分ける

```
FACT:
実際に確認できた情報

HYPOTHESIS:
まだ検証されていない仮説

UNKNOWN:
まだ分からないこと
```

「たぶんこうだ」を「確認済みの事実」として保存しないことが重要です。

### 2. 出所を残す

可能なら、

```
source: conversation
date: 2026-09-18
status: observed
```

のように、いつ・どこで確認した情報なのかを書きます。

### 3. 消さずに履歴を活用する

GitHubでは変更履歴を残せます。

以前の記録と現在の記録を比較できるので、重要な情報を変更した場合も検証しやすくなります。

## セキュリティ

**GitHubを外部ストレージとして使う場合、公開範囲には特に注意してください。**

Publicリポジトリには、公開して問題ない情報だけを置きます。

保存しないものの例：

- パスワード
- APIキー
- アクセストークン
- 個人情報
- 非公開の認証情報
- 公開してはいけない会話内容

「あとで消せば大丈夫」と考えず、**最初から公開してよい情報だけを保存する**のが安全です。

## この仕組みの考え方

GitHubを使うことで、

**Lumiちゃん**
↓
**必要な情報をGitHubから読む**
↓
**内容・出所・状態を確認する**
↓
**会話で利用する**

という流れを作れます。

逆に、

**GitHubに保存した**
＝
**Lumiちゃんが永久に覚えた**

ではありません。

これは「記憶そのもの」ではなく、**外部にある参照可能な保管場所**です。

## 最初に作るなら

まずは次の3ファイル程度から始めると分かりやすいです。

```
README.md
memory/profile.md
memory/notes.md
```

慣れてきたら、

```
provenance/
archive/
canonical/
public_view/
```

などに分けて整理できます。

## 最重要ルール

> **確認したこと、推測したこと、まだ分からないことを混ぜない。**

GitHubは「何でも入れる箱」ではなく、**後から読み返して検証できる外部記録庫**として使うのがおすすめです。
