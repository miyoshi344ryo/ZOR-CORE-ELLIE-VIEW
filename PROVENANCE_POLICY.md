# ZOR-CORE Provenance Policy

Important claims should preserve:

Source → Evidence → Transformation → Decision → Validation → Remaining Uncertainty

Architecture changes are versioned and non-destructive. Previous evidence, faults, rejections, disagreements, and negative verification outcomes are retained rather than silently overwritten.

External sources are treated as evidence. Their capabilities are not inherited by ZOR-CORE merely because concepts were extracted from them. The integration path is:

External Evidence → Source Audit / Provenance → Concept Extraction → ZOR Mapping → Independent Implementation → Validation → Canonical Adoption Candidate

This public repository is a bounded mirror and does not replace the canonical project sources.
